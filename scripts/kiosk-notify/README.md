# 窓処サーバへの「通話終了」通知

通話が終わったとき、お客様画面（窓処端末のブラウザ）から窓処サーバへ GET で知らせる仕組み。
窓処サーバはそれを受けて、窓処端末の画面を待機画面に戻す（**その制御は窓処端末アプリ側の担当**）。

## なぜブラウザから送るのか

窓処サーバは `localhost`、つまり**窓処端末そのもの**で動いている。
遠隔接客サーバ（Railway・インターネット上）から見た `localhost` は Railway 自身なので、**サーバー側からは届かない**。

窓処端末で動いているのは**お客様画面のブラウザ**。ここから `http://localhost:8080` を叩けば、
同じ機械の中なので届く。

```
係員が「終了」を押す ─┐
                      ├→ 遠隔接客サーバ → お客様画面（窓処端末のブラウザ）
お客様が「通話終了」を押す ─┘                    │
                                                  └→ GET http://localhost:8080?type=CALL_ENDED&…
```

**係員が終了した場合も、お客様画面が受け取ってから通知する。** 両方の経路が1か所に集まる。

## 送るもの（窓処側から示された通信方式・2026-08-20）

| 項目 | 内容 |
|---|---|
| プロトコル | HTTP GET |
| 送信先 | `http://localhost:8080`（**パスは付けない**） |
| データ形式 | クエリパラメータ |
| 切り替え | **`type` だけを見て**窓処側が判断する |

```
GET http://localhost:8080?type=CALL_ENDED&status=ended&route=client-call
    &machine=kiosk-1&session=session_…&ts=1787…&ver=1
```

窓処側の判断：

| `type` | 窓処側の動き |
|---|---|
| `INITIALIZED` | 通話画面に切り替える（**遠隔接客アプリは送っていない**。窓処端末アプリ側が送る） |
| `CALL_ENDED` | 通話終了と判断し、待機画面に戻す |

**終わり方は6種類あるが、すべて `type=CALL_ENDED` で送る。** 窓処側は `type` しか見ないため。
どの終わり方だったかは `status` に入れる（**窓処側は見なくてよい**。遠隔接客側の通話ログと
突き合わせるための記録）。

| `status` | 状況 |
|---|---|
| `ended` | どちらかが「通話終了」を押した |
| `staff-disconnected` | 通話中に係員の接続が切れた |
| `user-offline` | 通話中／呼び出し中にお客様側（窓処端末）の通信が切れた |
| `call-timeout` | 誰も応答しないまま打ち切り時間が過ぎた |
| `rejected` | 係員が応答を断った |
| `no-staff` | 応答できる係員がいなかった |

その他のパラメータ：`route`（窓処側の例に合わせた固定値 `client-call`）、
`machine`（端末ID）、`session`（通話ID）、`ts`（発生時刻・ミリ秒）、`ver`（`1`）。

**応答の中身は使わない。** 200 を返すだけでよい。
お客様画面は「投げっぱなし」で送るため、**CORSの設定も不要**。

### 送らない場合

**同じ端末から呼び直したとき、前の通話の終了は通知しない。**
窓処端末はそのまま新しい通話を始めているので、ここで `CALL_ENDED` を送ると
**始まったばかりの通話中に待機画面へ戻ってしまう**。

## 使い方

### 1. 確認用サーバを起動する

```bash
node scripts/kiosk-notify/mock-kiosk-server.mjs
```

`PORT=9000 node …` で番号を変えられる。受け取った通知は画面と `received.log` に出る。

### 2. お客様画面に通知先を渡して開く

```
https://…/user?machine=kiosk-1&name=券売機1番&station=…&notify=http://localhost:8080
```

通話して「通話終了」を押すと、確認用サーバの画面に通知が出る。

**`notify` に指定できるのは端末自身（`localhost` / `127.0.0.1` / `::1`）だけ。**
それ以外は無視する（細工したURLで端末を開かせ、外部へ通話の記録を送らせないため）。

## 確認済みのこと（2026-08-20・開発サーバで実測）

| 状況 | 結果 |
|---|---|
| 「通話終了」を押した | `status=ended` が届いた（通話IDつき） |
| 通話中にお客様側の通信が切れた | `status=user-offline` が届いた |
| 応答できる係員がいなかった | `status=no-staff` が届いた |
| 通話中に係員の接続が切れた | `status=staff-disconnected` が届いた |
| 通信が戻ってから呼び直した | **誤った `CALL_ENDED` は届かなかった**（上記「送らない場合」） |

`rejected` と `call-timeout` は同じ1か所から同じ形で送っており、他の4種類で経路は確認済み。

## 実機での確認用ページ `/kiosk-notify-test`

窓処端末は先方の持ち物で、キオスク運用のため開発者ツールを開けないことがある。
**ボタン1つで試せる確認用ページ**を用意してある。

```
https://…/kiosk-notify-test
```

やること：

1. 宛先（既定 `http://localhost:8080`）を確認し、リンクで受け取る側が生きているかを見る
2. 「通知を送ってみる」を押す。**本番と同じ `buildNotifyUrl` で組み立てたURL**を
   ①fetch ②画像の読み込み の2通りで送る
3. 結果と、報告してほしいことが画面に出る。「この結果をコピーする」でそのまま送れる

**このページだけでは届いたかどうかは判定できない**（応答を読まない送り方のため）。
判定は窓処サーバのログで行う。ログの照合用に `machine=notify-test` と
`via=fetch` / `via=img` を付けてある。

画面の「③ 参考：端末内への通信の許可設定」は**参考表示**。①が成功していれば
`denied` と出ていても問題ない（端末内から開いた場合など、許可の対象外でもそう出る）。

## 未確認事項（実機での確認が必要）

**HTTPSのページから `http://localhost` を呼べるか。**

上の確認は開発サーバ（`http://localhost:3001`）で行ったため、この点は確かめられていない。
**本番（HTTPS）の窓処端末で必ず確かめること。**

ブラウザは通常 HTTPS のページから HTTP への通信を遮断するが、`localhost` は例外扱いされるのが一般的。
ただし Chrome には **Private Network Access** という制限があり、インターネット上のページから
端末内への通信に事前確認（OPTIONS のプリフライト）を求める方向に進んでいる。

確認用サーバは、そのプリフライトに `Access-Control-Allow-Private-Network: true` を返すようにしてある。
**本物の窓処サーバでも同じ応答が必要になる可能性がある。**

送信は2段構えにしてある。①`fetch` で送り、②ブラウザに遮断されたら画像の読み込みで送り直す
（画像は CORS や Private Network Access の制限を受けにくい）。
どちらで送れたかは、お客様画面の開発者ツールの記録（`[窓処通知]`）で分かる。

遮断される場合の代替案：

| 案 | 内容 |
|---|---|
| A | 窓処サーバがプリフライトに応える（このサーバーと同じ実装） |
| B | 窓処サーバをHTTPSにする（自己署名証明書を端末に入れる） |
| C | 窓処端末アプリがお客様画面をWebViewに埋め込み、JavaScriptとネイティブの橋渡しで通知する |

**Cが最も確実**だが、窓処端末アプリ側の対応が必要。

## 窓処端末アプリ側で考慮が必要なこと

**ブラウザ自体が落ちた場合・端末の電源が切れた場合は通知できない。**
（通信断だけなら `localhost` はネットワークを経由しないので通知は送れる。）
そのため、**窓処端末アプリ側でも無通信のタイムアウト**
（例：一定時間 通話中の合図が来なければ待機画面に戻す）を持つ必要がある。
