# 退行テスト（デグレ防止）

機能追加・修正のたびに、**これまで直した不具合が再発していないか**を自動で確かめる道具です。
本番とまったく同じ通信の道（Socket.IO）を通し、必要なものは本物の画面（ヘッドレスChrome）で動かします。

## 使い方

```bash
npm run dev                    # 別の端末で開発サーバー（3001）を動かしておく
npm run test:regression        # 全部（約3分）
npm run test:regression:quick  # ソケットだけの速いもの（約1分・Chrome不要）
node scripts/regression/run.mjs --only=t3   # 1本だけ
```

**版を上げる（コミット・タグ・本番反映）前に、必ず全部合格させること。**
`eslint`（基準 31 件）と `tsc --noEmit` も合わせて確認する。

## 何を確かめているか

| ファイル | 版 | 直した不具合 | 確かめ方 |
|---|---|---|---|
| `t1-recall.mjs` | v1.48.0 | 呼び直すと、係員は通話中なのにお客様画面だけ言語選択へ戻る | お客様画面の動きを写した模型で最終的な画面を見る |
| `t2-order.mjs` | v1.49.0 | 分割確定の後半が前半を追い越して届く（順番の入れ替わり） | 長い前半→3ms後に短い後半。実際の翻訳APIで順番を見る |
| `t3-merge.mjs` | v1.51.0 | 分割された発話が塊ごとに訳され、文全体の意味が壊れる | 繋いだ全文・訳し直し・既読の宛先・記録が1件になること |
| `t6-ordering.mjs` | v1.52.0 | 先に話したお客様の発言が係員の返事の下に出る | 話し始めの時刻（spokeAt）で並ぶ・確定前の返答に印・変な時刻は捨てる |
| `t4-staffui.mjs` | v1.51/52 | （係員画面で）上の2つが見た目どおりか | 本物の係員画面を開いて吹き出しの数・順番・印を読む |

## 書き方の決まり

- 端末IDは必ず `test-` で始める（疑似係員はそれ以外の着信を**絶対に取らない**）
- 疑似係員の `uid` はテストごとに変える（同じだと前のテストの待機が残ったときに取り違える）
- 開発サーバー専用。`REGRESSION_BASE` に本番を指定しても `_lib.mjs` が止める
- 新しい不具合を直したら、**その不具合を再現する1本をここに足す**（直す前に落ち、直した後に通ることを確かめる）

## 自動では確かめられないもの

- 認識エンジンが発話を2つに分ける「分割確定」そのもの（合成音声では起きない。本物の人の声が要る）
- 認識エンジンの誤認識・語尾の打ち切り
- 翻訳の文脈の正しさ（参照訳との比較が要る）

これらは基本性能試験（人による実施）で見る。
